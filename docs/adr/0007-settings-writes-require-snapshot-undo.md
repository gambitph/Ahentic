# Settings writes require snapshot + undo

Theme settings, options, global styles, template parts, and media have no WordPress-native revision system — unlike posts, a bad write is permanent with nothing to fall back on. Any ability that writes one of these surfaces must snapshot the prior value (or its absence, e.g. an uncustomized template part with no database row) keyed to the session before executing, so `ahentic/undo-last-actions` can restore it. HITL alone was rejected as sufficient: it can be permanently disabled per-ability via `always_allow`, and a dry-run preview does not help once a write has already landed. `ahentic/replace-media-file` is the one exception, and must disclose the lack of undo coverage in its own HITL card rather than being silently exempted from this rule.
