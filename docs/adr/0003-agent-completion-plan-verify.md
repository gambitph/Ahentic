# Agent completion requires a plan; writes verify themselves

Ask mode ends when a good answer is delivered. Agent mode requires an explicit plan for multi-step work (≥2 tools or any write). Humans gate danger via HITL policy, not ordinary completion.

Completion does **not** require reading a write back. Write abilities already report what they persisted — server content abilities reload the post and return `content_text_chars`, editor abilities read the live block store back and return `text_chars` for the whole document — so a readonly re-check can only repeat what the orchestrator was already told. Calling one costs an extra LLM turn (browser reads cost two) and taught the model to re-read screens that cannot answer the question, most visibly by re-reading a stale admin page after a plugin change.

So verification is arithmetic on the write's own payload, in one place (`Ahentic_Finish_Gate::assess_write_payload`), and only for the failure a payload can reveal: a long-form run whose body is thinner than `LONG_FORM_MIN_CHARS`. Runs that are not long-form content work are not judged at all — tool success is the whole story. When a body is thin the verdict is marked on the tool result (`thin`, `thin_reason`), which the model reads in the think it was already going to have, so correction usually costs nothing. The finish gate (`Ahentic_Finish_Gate::evaluate_reply`) is only a backstop for replying anyway: one repair think (`MAX_VERIFY_ATTEMPTS`), then an honest partial finish. Findings are keyed by target document, so a later write supersedes an earlier one and chunked drafting accumulates instead of tripping on every section.

This supersedes the earlier tiered read-after-write rule. The prompt now forbids re-checking a successful write, and forbids using a page snapshot to confirm any change, since a snapshot reflects the page as rendered when it last loaded.
